# 修复剩余课程槽位计算逻辑 - 正确实现总限制约束

**日期：** 2025-08-22  
**类型：** 重要逻辑修复  
**影响范围：** 前端课程选择界面、剩余课程槽位计算、总限制显示  

## 变更概述

修复了前端剩余课程槽位计算逻辑中的关键问题，现在系统正确实现了"一个人总共只能报名2门课程"的总限制在前端界面的显示，确保用户无法在达到总限制后继续选择课程。

## 问题背景

### 用户反馈
```
我24年已经报了两门，25年就不可以在进行报名，红框内应该是不可在进行选择了
```

### 问题现象
从用户截图可以看到：
- **2024年秋季：2/3门课程**（已报名2门）
- **总报名2门课程**
- **红框内显示"还可以选择2门课程"** ❌

这是错误的！如果2024年已经报名2门课程，总报名数量就是2门，按照总限制"一个人总共只能报名2门课程"，2025年就不应该再能选择任何课程了。

### 问题分析
1. **前端计算逻辑错误**：`remainingCourseSlots`只考虑了学期内限制，没有考虑总课程数量限制
2. **显示不一致**：后端已经正确实现了总限制，但前端显示仍然允许选择课程
3. **用户体验问题**：用户看到可以选择的提示，但实际提交时会失败

## 解决方案

### 1. 前端逻辑修复

**文件：** `frontend/src/views/Registration.vue`

**修复内容：**
- 修复`updateEnrollmentLimits`函数中的`remainingCourseSlots`计算逻辑
- 优先考虑总课程数量限制
- 确保总限制达到后，剩余槽位为0

**修复前代码：**
```typescript
enrollmentLimits.remainingCourseSlots = Math.max(0, limits.semesterLimit - limits.currentTotal)
```

**修复后代码：**
```typescript
// 🔧 修复：考虑总课程数量限制
// 如果总报名数量已经达到2门，则不能再报名
if (limits.totalEnrollments >= 2) {
  enrollmentLimits.remainingCourseSlots = 0
} else {
  // 否则按学期限制计算
  enrollmentLimits.remainingCourseSlots = Math.max(0, limits.semesterLimit - limits.currentTotal)
}
```
