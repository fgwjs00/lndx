# 修复2024年秋季学期报名限制验证逻辑的问题

**日期：** 2025-08-22  
**类型：** 重要逻辑修复  
**影响范围：** 报名系统、课程数量限制验证、跨学期报名逻辑  

## 变更概述

修复了2024年秋季学期报名限制验证逻辑的问题，现在系统能够正确识别用户选择的学期并应用相应的课程数量限制政策，确保2024年秋季学期的学生可以报名3门课程。

## 问题背景

### 用户反馈
```
Failed to load resource: the server responded with a status of 400 (Bad Request)
提交失败: Error: 最多只能选择2门课程
我们2024年是可以报名3门课程的呀
```

### 问题现象
1. **前端显示正确**：显示"2024年秋季特殊政策：最多可报名3门课程"
2. **后端验证错误**：仍然返回"最多只能选择2门课程"的错误
3. **政策不一致**：前端显示3门课程限制，但后端验证时限制为2门

### 问题原因
**核心问题**：后端验证逻辑使用了错误的学期信息
1. **前端用户选择**：`semester: '2024年秋季'`
2. **后端验证使用**：`firstSelectedCourse.semester`（从课程表获取的学期）
3. **逻辑错误**：如果课程的`semester`字段不是"2024年秋季"，验证就会失败

**具体分析**：
- 用户选择"2024年秋季"学期
- 但后端验证时查询所选课程的`semester`字段
- 如果课程的`semester`字段值与用户选择的不一致，就会导致验证失败
- 系统应该使用用户选择的学期进行验证，而不是课程的学期

## 解决方案

### 修复逻辑
**文件：** `backend/src/routes/applicationV2.ts`

**修复内容**：
- 将验证逻辑从使用`firstSelectedCourse.semester`改为使用`applicationData.semester`
- 确保验证使用用户实际选择的学期，而不是课程的学期

**修复前代码**：
```typescript
// 查询第一门所选课程的学期信息
const firstSelectedCourse = await tx.course.findUnique({
  where: { id: applicationData.selectedCourses[0] },
  select: { semester: true }
})

if (firstSelectedCourse?.semester) {
  // 使用新的跨学期限制验证
  const validation = validateCourseSelection(
    firstSelectedCourse.semester,  // ❌ 错误：使用课程的学期
    activeEnrollments.map((e: any) => ({
      course: { semester: e.course?.semester || '' },
      status: e.status
    })),
    applicationData.selectedCourses.length
  )
  // ...
}
```

**修复后代码**：
```typescript
// 🔧 修复：使用用户选择的学期进行验证，而不是课程的学期
// 用户选择"2024年秋季"就应该按照"2024年秋季"的政策进行验证
const userSelectedSemester = applicationData.semester

if (userSelectedSemester) {
  // 使用新的跨学期限制验证
  const validation = validateCourseSelection(
    userSelectedSemester,  // ✅ 正确：使用用户选择的学期
    activeEnrollments.map((e: any) => ({
      course: { semester: e.course?.semester || '' },
      status: e.status
    })),
    applicationData.selectedCourses.length
  )
  // ...
}
```

### 修复位置
修复了两个相同的代码块：
1. **第一个实例**：第207-232行（现有学生验证逻辑）
2. **第二个实例**：第660-685行（重复的验证逻辑）
